# 배포와 자동 검사·배포(CI/CD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사이트를 Lightsail 서버 한 대에 Docker Compose(Caddy + Spring Boot + PostgreSQL)로 올리고, `main`에 푸시하면 테스트 → 이미지 → 서버 교체 → 상태 확인(실패 시 되돌리기)이 자동으로 돌게 한다.

**Architecture:** 로그인 정보는 Spring Session JDBC로 DB에 둔다. 운영 설정은 `prod` 프로필 하나에 모은다. 이미지는 백엔드(`backend/Dockerfile`)와 화면+Caddy(`deploy/web.Dockerfile`) 두 개이고 커밋 SHA 태그로 ghcr.io에 올린다. 서버에서는 `deploy.sh`가 `.env`의 `IMAGE_TAG`만 바꿔 교체·확인·되돌리기를 한다.

**Tech Stack:** Spring Boot 4.1.2 + Spring Session JDBC, Flyway, Docker / Docker Compose, Caddy 2, GitHub Actions, ghcr.io, AWS Lightsail(Ubuntu 24.04).

**Spec:** `docs/superpowers/specs/2026-10-25-deploy-design.md`

## Global Constraints

- 작업 가지: `dev`에서 `deploy` 가지를 만들어 작업하고, 끝나면 `dev`에 합친다. `main` 합치기와 모든 푸시는 사용자가 요청할 때만.
- 커밋 이메일은 저장소 로컬 설정 그대로(`48915312+yyy5044@users.noreply.github.com`). 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- DB 변경은 새 Flyway 파일 `V10__spring_session.sql`로만.
- 이미지 이름: `ghcr.io/yyy5044/aram-backend:<SHA>`, `ghcr.io/yyy5044/aram-web:<SHA>`. 서버 폴더: `/opt/aram`(`compose.yaml`, `deploy.sh`, `.env`).
- 비밀 값은 서버 `/opt/aram/.env`와 GitHub Secrets(`DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`)에만. 저장소 파일에는 이름만. 이미지 안에 `.env`가 들어가면 안 된다.
- 메모리: `backend` 1200m(JVM `-XX:MaxRAMPercentage=70`), `db` 512m. 로그 `json-file` 10m × 3.
- 화면 문구는 해요체. 업데이트 중 안내 문장은 정확히:
  - 페이지: "잠시 업데이트 중이에요. 조금 뒤에 새로고침해 주세요."
  - API: `{"code":"MAINTENANCE","message":"잠시 업데이트 중이에요. 조금 뒤에 다시 시도해 주세요."}` (서버 `ErrorResponse`처럼 `fieldErrors`가 없으면 생략)
- 상태 확인: `http://127.0.0.1:8080/actuator/health`가 `"status":"UP"`이 될 때까지 최대 180초.
- Docker Desktop을 에이전트 셸에서 켜지 않는다. `docker info`가 실패하면 사용자에게 켜달라고 한다.
- 셸 명령 하나에 heredoc 여러 개를 묶지 않는다. 파일은 하나씩 쓴다.

## Review Focus

- 첫 배포(직전 버전이 없음)에서 상태 확인이 실패하면 `deploy.sh`는 빈 태그로 "되돌리기"를 하지 말고 실패를 분명히 알리고 끝나야 한다 → Task 4 리허설 Step.
- 서버 `.env`에 `IMAGE_TAG` 줄이 아직 없을 때(처음) `deploy.sh`가 줄을 더해야 한다. 다른 줄(비밀번호 등)은 건드리지 않는다 → Task 4 리허설 Step.
- 하위 주소 새로고침(`/augments?open=…`, `/posts/1`)은 `index.html`을 받아야 하지만, 없는 `/assets/*.js`는 `index.html`이 아니라 404여야 한다(아니면 브라우저가 HTML을 스크립트로 읽어 흰 화면) → Task 3 Caddyfile, Task 4 리허설 Step.
- 백엔드 컨테이너를 새 것으로 바꿔도 세션 행이 남아 같은 `SESSION` 쿠키가 계속 통해야 한다 → Task 1 테스트 + Task 4 리허설 Step.
- 바깥에서 `X-Forwarded-Proto`를 속여 보내거나 `/actuator`에 닿을 수 없어야 한다(백엔드 포트는 `127.0.0.1`에만) → Task 4 리허설 Step.

**Interfaces:**
- Consumes: Task 3의 이미지 이름과 포트.
- Produces: `deploy.sh <TAG> <GHCR_USER>` — 표준 입력으로 ghcr 토큰을 받는다(빈 입력이면 로그인·받기를 건너뛴다: 로컬 리허설용). `/opt/aram`이 아니라 **스크립트가 있는 폴더**에서 동작한다. 종료 코드 0 = 새 버전 정상, 1 = 실패(되돌렸거나 되돌릴 버전 없음).

- [ ] **Step 2: `.env.prod.example`** — `DOMAIN=`, `POSTGRES_PASSWORD=`, `DISCORD_CLIENT_ID=`, `DISCORD_CLIENT_SECRET=`, `APP_ADMIN_DISCORD_IDS=`, 각 줄 위에 한국어 설명. `IMAGE_TAG`는 "deploy.sh가 관리해요" 주석만.
- [ ] **Step 3: `deploy.sh`** — `bash`, `set -euo pipefail`. 순서(설계 6.3):
  1. `.env`에서 `IMAGE_TAG` 값을 `PREVIOUS`로 읽는다(없으면 빈 값).
  2. 표준 입력 토큰이 있으면 `docker login ghcr.io -u <GHCR_USER> --password-stdin` → `docker compose pull backend web` → `docker logout ghcr.io`.
  3. `.env`의 `IMAGE_TAG` 줄만 새 태그로 바꾸고, 줄이 없으면 끝에 더한다.
  4. 스크립트 폴더에서 `docker compose up -d`(그 폴더의 `compose.yaml` — 서버와 리허설 모두 `compose.prod.yaml`을 이 이름으로 복사해 둔다).
  5. 3초마다 `curl -fsS http://127.0.0.1:8080/actuator/health`에서 `"status":"UP"`을 찾는다. 180초.
  6. 실패: `PREVIOUS`가 있으면 `IMAGE_TAG`를 되돌리고 `up -d`, "직전 버전(<PREVIOUS>)으로 되돌렸어요" 출력. 없으면 "되돌릴 버전이 없어요" 출력. 둘 다 `docker compose logs --tail 100 backend` 출력 후 `exit 1`.
  7. 성공: `docker image prune -af --filter "until=168h"`, "배포 완료: <TAG>" 출력.
- [ ] **Step 4: 로컬 리허설 준비** — 스크래치 폴더에 `compose.yaml`(=`compose.prod.yaml` 복사), `deploy.sh`, `.env`(`DOMAIN=localhost`, 영문·숫자 32자 무작위 비밀번호, 디스코드 값은 가짜) 를 두고, Task 3의 `:local` 이미지를 쓴다. Git Bash에서 `echo -n | bash deploy.sh local x`.
- [ ] **Step 5: 리허설 확인** — 모두 기대대로여야 한다.
  - `deploy.sh`가 "배포 완료: local"로 끝나고 `.env`에 `IMAGE_TAG=local`이 생겼고, 다른 줄은 그대로다.
  - `curl -k https://localhost/` → 200, `<div id="root">`. `curl -k https://localhost/augments?open=x` → 200 같은 HTML. `curl -k -o /dev/null -w '%{http_code}' https://localhost/assets/nope.js` → 404.
  - `curl -k https://localhost/api/patches` → 200 JSON. `curl -k -o /dev/null -w '%{http_code}' https://localhost/actuator/health` → `index.html`(200 HTML)이지 JSON이 아니다. `docker compose port backend 8080` → `127.0.0.1:8080`.
  - `curl -k -i https://localhost/oauth2/authorization/discord` → `Location`의 `redirect_uri`가 `https://localhost/login/oauth2/code/discord`, `SESSION` 쿠키에 `Secure`. 그 쿠키 값의 행이 `spring_session`에 있다. `docker compose restart backend` 뒤에도 그 행이 남아 있다.
  - `docker compose stop backend` → `curl -k -i https://localhost/` 503 + 안내 문장, `curl -k https://localhost/api/patches` → 503 + `MAINTENANCE` JSON. 다시 `start`.
  - 되돌리기: 뜨지 않는 버전을 흉내 낸다. `docker build -t ghcr.io/yyy5044/aram-backend:broken - <<< $'FROM ghcr.io/yyy5044/aram-backend:local\nENTRYPOINT ["false"]'`, `docker tag ghcr.io/yyy5044/aram-web:local ghcr.io/yyy5044/aram-web:broken`. `deploy.sh broken x` → `exit 1`, "직전 버전(local)으로 되돌렸어요", `.env`는 `IMAGE_TAG=local`, 사이트 다시 200.
  - 첫 배포 실패: `.env`에서 `IMAGE_TAG` 줄을 지우고 `deploy.sh broken x` → `exit 1`, "되돌릴 버전이 없어요".
  - 정리: `docker compose down -v`, `:broken` 이미지 지우기.
- [ ] **Step 6: 커밋** — `deploy/` 세 파일. `"Add the production compose file and a deploy script that rolls back on failure"`.
