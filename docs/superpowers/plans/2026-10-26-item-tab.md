# 아이템 탭·아이템 태그 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 증강 칼바람 상점 아이템을 받아 칼바람 수치로 설명을 완성해 저장하고, 아이템 탭(`/items`)·태그 페이지·글 아이템 태그·본문 `@` 아이템 박스와 설명 상자를 만든다.

**Architecture:** 기존 게임 데이터 동기화가 증강 다음에 아이템 단계를 돈다. 큰 bin 파일 두 개(`map12`, `items.cdtb`)는 스트리밍으로 필요한 최상위 항목만 읽고, 순수 함수 묶음(`gamedata/item/`)이 상점 목록·단계·수치(Kiwi>ARAM>기본)·설명을 만든다. 설명은 증강 계산기(`gamedata/text/`)를 그대로 쓴다. 글 태그는 증강 태그(`post_augments`)와 같은 모양의 `post_items`로, 화면은 증강 탭·태그 칸·`@` 메뉴 부품에 `item` 종류를 더한다.

**Tech Stack:** Spring Boot 4.1 / JPA / Flyway / Jackson 3 스트리밍(`tools.jackson.core.JsonParser`); React 19, TanStack Query, Tiptap 3, `@floating-ui/dom`, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-item-tab-design.md`

## Global Constraints

- 가지 `item-tab`(이미 있음, 설계 문서 커밋됨). 끝나면 `dev`에 합친다. 푸시는 사용자 요청 때만. 바닥글 변경은 이미 `dev`에 있다.
- 증강 칼바람 = `Maps/Shipping/Map12/Modes/KIWI`. 수치 우선순위 `DataValuesModeOverride.Kiwi` > `.ARAM` > `mDataValues`.
- 살 수 있는 아이템만: `mItemDataAvailability.mInStore != false`, 총가격 > 0, `mRequiredChampion` 없음. 아이템 bin에 없는 번호는 건너뛴다.
- 단계(`ItemTier`, 이 순서로 화면에 보임): `AUGMENT_MODE`(증강 칼바람 전용) · `LEGENDARY`(전설) · `EPIC`(서사) · `BOOTS`(신발) · `BASIC`(기본) · `STARTER`(시작·소모품). 판정 순서: epicness 8 → AUGMENT_MODE, 분류(`mCategories`) `Boots` → BOOTS, 분류 `Consumable` 또는 epicness 0·1·3 → STARTER, 7 → AUGMENT_MODE, 5 → LEGENDARY, 4 → EPIC, 2·없음 → BASIC. epicness는 `ItemData` 최상위 `epicness`만 쓴다(`mItemDataClient.epicness`는 상점 묶음과 다른 값이라 쓰지 않는다. 예: 6032 추가 능력치는 최상위 8이고 분류에 Consumable이 있다).
- 번호는 DB `int`, API·주소·본문 박스·요청에서는 문자열(`"3084"`).
- 한도: 아이템 태그 칸 10개, `@` 후보 8개(종류 섞어서), 본문 박스 30개(기존).
- 문구(해요체, 그대로): "아이템은 10개까지 고를 수 있어요", "없는 아이템이 들어 있어요", "현재 게임에 없는 아이템은 새로 붙일 수 없어요", "없는 챔피언·증강·아이템이 들어 있어요", "없는 아이템이에요"(404 `ITEM_NOT_FOUND`), "아직 아이템 정보를 받아오지 못했어요", "아직 설명이 없어요", "불러오는 중…", "아이템 정보를 불러오지 못했어요", "아이템 이름 검색", 묶음 이름 "증강 칼바람 전용"·"전설"·"서사"·"신발"·"기본"·"시작·소모품", 상자 머리 "{가격} 골드 · {묶음 이름}", 상자 줄 제목 "재료"·"상위 아이템", 메뉴 오른쪽 "아이템", 박스 `aria-label` "{이름} 아이템 설명 보기", 태그 칸 제목 "아이템", 자리표시 "아이템 검색…".
- 색 표식 허용 목록은 서버 `AugmentDescriptionBuilder.COLOR_TAGS`와 화면 `lib/augmentDescription.ts`가 같아야 한다(CLAUDE.md).

## Review Focus

- 재료나 상위 아이템이 상점 목록에 없는 아이템(예: 협곡 전용 재료) → 그 아이콘만 빠지고 상자가 깨지지 않아야 한다 → Task 2 `buildCatalog` 테스트(상점 밖 재료는 `fromIds`에 남기되 화면이 거른다), Task 8 `ItemTooltip` 테스트(목록에 없는 번호는 안 그림).

- 아이템 단계만 실패(맵 파일 404) → 챔피언·증강은 저장되고 이전 아이템은 그대로, 결과는 FAILED(30분 뒤 재시도) → Task 4 테스트.
