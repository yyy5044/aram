# 아이템 탭 상점 구조 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 아이템 탭을 롤 상점 구조(능력치 걸러내기·단계별 줄·조합 나무·상위 아이템·휴대폰 아래 창)로 바꾸고, 글의 아이템 태그를 서버·화면·DB에서 없앤다.

**Architecture:** 서버는 아이템마다 게임 자료의 `mCategories`를 `items.categories`로 저장해 `GET /api/items`로 내보낸다. 화면은 그 목록 하나로 걸러내기·검색·줄·나무를 모두 계산하는 순수 함수(`lib/itemStats.ts`, `lib/itemShop.ts`)와, 그걸 그리는 `ItemsPage`·`ItemDetailPanel`·`BottomSheet`로 나눈다. 아이템 태그는 `post_items`부터 화면 칩까지 한 번에 걷어낸다(본문 `@` 아이템은 남김).

**Tech Stack:** Spring Boot 4.1, JPA, Flyway, PostgreSQL 18, React 19, TypeScript, Tailwind CSS 4, TanStack Query, React Router, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-26-item-shop-design.md`

## Global Constraints

- DB 변경은 새 Flyway 파일로만: `V14__item_categories.sql`, `V15__drop_post_items.sql`. Hibernate `ddl-auto: validate`.
- V14는 `current_cdragon_version`만 비운다(`current_ddragon_version`은 건드리지 않는다).
- 능력치 버튼 15개와 분류 대응은 스펙 5장 표 그대로, 화면 `lib/itemStats.ts` 한 곳에.
- 여러 능력치 버튼은 모두 맞아야(AND), 버튼 하나 안의 분류는 하나라도 맞으면(OR).
- 줄 순서: 증강 칼바람 전용 → 시작·소모품 → 신발 → 기본 → 서사 → 전설. 줄 안은 총가격 오름차순, 같으면 `nameKo` 가나다순.
- 화면 폭: 넓은 화면 `lg`(1024px 이상) 세 칸, 중간 `md`(768~1023px) 두 칸, 휴대폰(768px 미만) 한 칸 + 아래 창.
- 주소: 고른 아이템만 `?item=<번호>`, 바꿀 때 `replace`. 능력치·검색어는 주소에 남기지 않는다.
- 화면 문구(해요체, 정확히): `아이템`, `아이템 n개`, `모든 아이템`, `아이템 이름 검색`, `조건에 맞는 아이템이 없어요`, `조건 지우기`, `조합 나무`, `만들 수 있는 아이템`, `아이템을 고르면 조합과 설명이 나와요`, `설명을 불러오지 못했어요`, `닫기`, `아직 아이템 정보를 받아오지 못했어요. 잠시 후 다시 확인해주세요`, 가격 `3000 골드 · 전설`.
- 색·모서리·글꼴은 `index.css` `@theme` 이름만, 버튼은 `components/ui/button.ts`의 `buttonClass`(뒤에 높이·색 덧붙이지 않기).
- 본문 `@` 아이템(`lib/mentionCandidates.ts`, `TagMentionChip`, `components/item/ItemTooltip*`)과 서버의 `tagMention kind:item` 검사는 그대로 둔다.
- 실행: 백엔드 `cd backend && ./gradlew test`, 화면 `cd frontend && npm test && npm run build && npm run lint`(Git Bash는 `export PATH="/c/Program Files/nodejs:$PATH"`).
- 커밋 메시지 끝 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, 작업 가지 `item-shop`.

## Review Focus

1. 걸러내기 결과가 비면 고른 아이템이 줄에서 사라져도 오른쪽 칸(또는 아래 창)은 그대로 남아야 한다 → Task 5 `keepsSelectionWhenFilteredOut`.
2. 재료가 같은 아이템 두 개(예: 장검 2개)면 나무에 두 칸 그려야 한다(중복 제거 금지) → Task 4 `treeKeepsDuplicateIngredients`.
3. 휴대폰 창을 닫으면 초점이 누른 아이템 칸으로 돌아가야 한다(키보드 사용자) → Task 5 `sheetReturnsFocusToItem`.
4. 옛 글 수정 화면을 열어도 아이템 태그 때문에 깨지지 않아야 한다(응답에 `items`가 없음) → Task 3 `editFormWithoutItems`.
5. 재료를 따라가 자기 자신을 다시 가리키는 잘못된 자료에서 나무가 끝없이 그려지면 안 된다 → Task 4 `treeStopsOnCycle`.
