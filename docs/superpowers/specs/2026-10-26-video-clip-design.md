# 영상 클립 블록 설계

- 작성일: 2026-10-26
- 상태: 사용자가 대화에서 화면·서버 설계를 승인함. 이 문서는 검토 대기.

## 1. 목적

친구들이 게임 장면(펜타킬, 조합 시연 등)을 글에 쉽게 넣게 한다. 노션처럼 글을 쓰다 `/`로 영상 칸을 만들고, 파일을 끌어다 놓으면 서버가 정해진 규격으로 줄여서 **소리 없이 자동 반복되는 짧은 클립**으로 넣는다. 원본은 저장하지 않아 서버 디스크(약 50GB 여유)를 아낀다.

**성공 기준**
1. 글쓰기에서 `/`를 치면 영상·사진 메뉴가 뜨고, 영상을 고르면 본문 안에 점선 영상 칸이 생긴다. 도구 줄의 영상 버튼으로도 같은 칸이 생긴다.
2. 칸에 영상을 끌어다 놓거나(PC) 칸을 눌러 고르면(PC·휴대폰) 올라가고, "올리는 중 n%" → "변환 중 n%"가 차오른 뒤 그 자리에서 클립이 재생된다.
3. 저장된 클립은 30초 이하, 720p 이하, 24fps, 소리 없음, MP4다. 30초 클립이 약 3~6MB.
4. 글을 볼 때 클립은 화면에 보이면 소리 없이 자동 반복되고, 누르면 멈췄다가 다시 누르면 이어진다. iPhone Safari에서도 재생된다.
5. 원본 파일은 변환이 끝나거나 실패하면 서버에서 지워진다.
6. 화면을 조작해도 남의 영상, 변환이 안 끝난 영상, 바깥 주소의 영상을 글에 넣을 수 없다.

## 2. 범위

**포함**: `/` 메뉴(영상·사진), 도구 줄 영상 버튼, 영상 칸(빈 칸·올리는 중·변환 중·완료·실패), 사진 칸(`/i`, 놓으면 지금의 사진 올리기로 바로 사진이 됨), 서버 변환(ffmpeg, 한 번에 하나), 진행률 조회, 영상 내려주기(Range 지원), 본문 규칙에 `video` 노드 추가, 쓰이지 않은 영상 정리, 운영 이미지·메모리 설정 변경.

**제외**: 소리 켜기, 구간 고르기(앞 30초만 씀), 댓글에 영상, 브라우저 쪽 변환, 변환 전용 컨테이너, 글 목록에 영상 미리보기, `/` 메뉴의 다른 블록(목록·인용 등은 지금 도구 줄 그대로).

## 3. 화면

### 3.1 `/` 메뉴

- 편집기에서 줄 맨 앞이거나 공백 뒤에 `/`를 치면 커서 아래에 메뉴가 뜬다. 항목은 **영상**(`/v`)과 **사진**(`/i`) 두 개.
- `/` 뒤에 친 글자로 거른다: `v`·`영` → 영상, `i`·`사` → 사진. 맞는 게 없으면 메뉴를 닫고 친 글자는 그대로 둔다.
- 위·아래 화살표로 고르고 Enter(또는 누르기)로 넣는다. 넣으면 `/v` 같은 친 글자는 지워지고 그 자리에 칸이 생긴다. Esc는 메뉴만 닫는다.
- 메뉴 모양은 디자인 규칙을 따른다: surface 바탕, line 테두리, `shadow-pop`, 항목 높이 40, 고른 항목 ice 바탕, 오른쪽에 `/v`·`/i` 작은 글자(ink-3, 13px).
- 도구 줄의 사진 버튼 옆에 **영상** 버튼을 둔다(누르면 커서 자리에 영상 칸).
- 빈 본문 안내 문구: "/를 입력하면 영상·사진을 넣을 수 있어요".

### 3.2 영상 칸

본문 폭 전체, 높이 160의 점선(2px, line 색) 네모. 각지게(모서리 0). 단계별 모습:

| 단계 | 보이는 것 |
|---|---|
| 비어 있음 | 가운데 재생 아이콘, "파일을 업로드해주세요"(15px), 아래 "끌어다 놓거나 눌러서 고르기 · 30초 · 200MB까지"(13px ink-3). 파일을 끌어 올리면 테두리 teal, 바탕 ice. 칸을 누르면 파일 고르기(`accept="video/*"`) |
| 올리는 중 | 진행 막대(teal) + "올리는 중 45%" |
| 변환 중 | 진행 막대 + "변환 중 62%". 줄을 서 있으면 "변환 차례를 기다리고 있어요" |
| 완료 | 클립이 그 자리에서 자동 반복(글 보기와 같은 재생). 30초를 넘었던 영상이면 아래 "앞 30초만 넣었어요"(13px ink-3) |
| 실패 | 칸 안에 서버가 준 오류 문장(danger) + **다른 파일 올리기** 버튼(`buttonClass('ghost', 36)`) |

- 칸을 고른 상태(완료 포함)에서 오른쪽 위에 ✕ 버튼(`aria-label="영상 빼기"`)으로 칸을 지운다. **변환이 끝난 클립은 ✕ 버튼으로만 지울 수 있다**(2026-10-26 사용자 요청: 글을 쓰다 실수로 지우지 않게). Backspace·Delete·범위 지우기·잘라내기로 클립이 줄어드는 변경은 막고, 막히면 "영상은 오른쪽 위 ✕ 버튼으로 뺄 수 있어요"를 3초에 한 번까지 띄운다. 끌어서 옮기기는 된다. 빈 칸·올리는 중인 칸은 키보드로도 지워진다. 클립이 채워지는 변경은 되돌리기 기록에 남기지 않는다.
- 바로 막는 경우(올리지 않음):
  - 영상이 아닌 파일: "영상 파일만 넣을 수 있어요"
  - 200MB 초과: "영상 파일은 200MB까지 올릴 수 있어요"
  - 이미 영상 3개: "영상은 한 글에 3개까지 넣을 수 있어요"
  - 알림은 지금의 알림(아래 가운데)으로 보여준다.
- 사진 칸(`/i`)은 같은 점선 칸("사진을 업로드해주세요 · 끌어다 놓거나 눌러서 고르기")이고, 사진을 놓으면 지금의 사진 올리기를 그대로 써서 칸이 사진으로 바뀐다. 사진 규칙(10MB·10장·형식)은 지금 그대로.

### 3.3 등록

- 본문에 올리는 중이거나 변환 중인 영상 칸이 있으면 등록 띠의 **등록** 버튼을 잠그고 버튼 옆에 "영상 변환이 끝나면 등록할 수 있어요"(13px ink-3)를 보여준다.
- 실패한 칸이 있으면 등록할 때 "변환하지 못한 영상을 빼거나 다시 올려 주세요"를 띄우고 막는다.
- 파일을 넣지 않은 빈 칸(영상·사진)은 저장할 때 본문에서 빠진다.
- 변환 중에 창을 닫아도 서버는 끝까지 변환한다. 글에 안 쓰인 영상은 하루 뒤 지워진다(사진과 같음).

### 3.4 글 보기

- 클립은 본문 폭에 맞춰 원래 비율로 보인다(최대 높이 없음, 세로 영상은 가운데 정렬·최대 너비 360).
- `<video muted loop playsinline preload="metadata" poster=첫장면>`. 화면에 반 이상 보이면 재생, 벗어나면 멈춘다(IntersectionObserver).
- 누르면 멈춤/재생을 바꾼다. 멈춰 있으면 가운데에 반투명 원 안의 ▶ 표시. `aria-label`은 "영상 멈추기"/"영상 재생".
- 브라우저가 자동 재생을 막으면(절전 모드 등) 멈춘 모습(▶)으로 시작한다.
- 글 고치기에서도 같은 칸으로 보이고, 지우거나 더 넣을 수 있다.

## 4. 서버

### 4.1 데이터 (Flyway `V11__videos.sql`)

`videos` 표:

| 칼럼 | 타입 | 설명 |
|---|---|---|
| id | uuid PK | |
| uploader_id | bigint not null → users | |
| post_id | bigint → posts, on delete set null | 쓰인 글 |
| status | varchar(20) not null | `QUEUED`, `PROCESSING`, `READY`, `FAILED` |
| progress | smallint not null default 0 | 0~100 |
| error_message | varchar(200) | 실패 때 화면에 그대로 보여줄 문장 |
| truncated | boolean not null default false | 30초를 넘어 앞부분만 썼는지 |
| storage_key | varchar(200) | 완료 뒤 `videos/{id}.mp4` |
| poster_key | varchar(200) | 완료 뒤 `videos/{id}.jpg` |
| width, height | int | 완료 뒤 |
| duration_ms | int | 완료 뒤 |
| size_bytes | int | 완료 뒤 |
| created_at | timestamptz not null | |

인덱스: `(post_id)`, 쓰이지 않은 영상 정리용 `(created_at) where post_id is null`, 시작 시 정리용 `(status)`.

### 4.2 API

| 메서드·주소 | 설명 |
|---|---|
| `POST /api/videos` (multipart `file`) | 닉네임 필요. 200MB 이하, 영상인지 확인(아래). 원본을 임시 폴더에 저장하고 `QUEUED` 행을 만든 뒤 변환 줄에 넣는다. 응답 `{ id, status, progress }` |
| `GET /api/videos/{id}/status` | 올린 사람만(다른 사람이면 404 `VIDEO_NOT_FOUND`). `{ status, progress, truncated, url, posterUrl, width, height, errorMessage }`. 화면이 1초마다 부른다 |
| `GET /api/videos/{id}` | 누구나. `READY`인 MP4를 `Range` 요청까지 지원해 내려준다(iPhone 재생에 필요). `Cache-Control: public, max-age=31536000, immutable`. 없거나 준비 안 됐으면 404 |
| `GET /api/videos/{id}/poster` | 누구나. 첫 장면 JPEG, 같은 캐시 |

오류 코드(`ErrorCode`)를 더한다: `VIDEO_TOO_LARGE`("영상 파일은 200MB까지 올릴 수 있어요"), `VIDEO_UNSUPPORTED`("영상 파일만 넣을 수 있어요"), `VIDEO_NOT_FOUND`("영상을 찾을 수 없어요").

- 영상 판별: 파일 앞부분의 형식 표시(MP4/MOV의 `ftyp`, WebM/MKV의 EBML 머리)로 1차 확인하고, 변환 전 `ffprobe`로 영상 흐름이 있는지 다시 확인한다. 아니면 `FAILED`("영상 파일만 넣을 수 있어요").
- multipart 한도는 전체 210MB로 올린다. 사진은 지금처럼 `ImageService.MAX_BYTES`(10MB)로 따로 막는다.

### 4.3 변환

- `video` 패키지에 `VideoTranscoder`(ffmpeg 실행·진행률 해석)와 `VideoQueue`(단일 작업 스레드)를 둔다. 변환 부분은 인터페이스로 떼어 나중에 다른 곳으로 옮기기 쉽게 한다.
- 한 번에 하나만 변환한다. 줄에서 꺼내면 `PROCESSING`.
- ffmpeg 설정(값 고정):
  - `-t 30`(앞 30초), 원본 길이가 30초를 넘으면 `truncated=true`
  - `-vf "scale='min(1280,iw)':'min(720,ih)':force_original_aspect_ratio=decrease:force_divisible_by=2,fps=24"`
  - `-an`(소리 없음), `-c:v libx264 -preset veryfast -crf 28 -pix_fmt yuv420p -profile:v high -movflags +faststart`
  - `-threads 2`
  - 첫 장면 JPEG: `-frames:v 1`, 같은 크기, 품질 `-q:v 4`
- 진행률: `-progress pipe:1`의 `out_time_us`를 `min(원본 길이, 30초)`로 나눠 0~99로 저장하고, 끝나면 100·`READY`. DB 쓰기는 1초에 한 번 이하.
- 변환 제한 시간 3분. 넘거나 ffmpeg가 실패하면 `FAILED`("변환하지 못했어요. 다른 파일을 올려 주세요").
- 끝나면(성공·실패 모두) 원본 임시 파일을 지운다.
- 서버가 켜질 때 `QUEUED`·`PROCESSING` 행은 `FAILED`("서버가 다시 켜져서 변환이 멈췄어요. 다시 올려 주세요")로 바꾸고 임시 폴더를 비운다.
- 임시 폴더는 `app.videos.tmp-dir`(개발 `data/video-tmp`, 운영 `/data/images/tmp`로 같은 볼륨 안).
- 저장은 지금의 `ImageStorage`를 그대로 써서 `videos/{id}.mp4`, `videos/{id}.jpg` 키로 둔다(운영에서는 `images` 볼륨 안 `videos/` 폴더). Range 응답을 위해 `ImageStorage`에 파일 경로를 돌려주는 메서드를 더한다.

### 4.4 본문 규칙

- 본문 노드에 `video`를 더한다: `{ "type": "video", "attrs": { "src": "/api/videos/{uuid}" } }`. 서버 `PostContentValidator`와 화면 `editor/extensions.ts`, `editor/extensions.test.ts`를 함께 바꾼다(CLAUDE.md 규칙).
- 제목과 클립(또는 사진)만 있고 글자가 없는 본문도 저장된다(2026-10-26 사용자 결정). 글자·사진·영상이 모두 없을 때만 "본문을 입력해주세요".
- 서버 검사: `src`는 위 형식만, 한 글에 3개까지("영상은 한 글에 3개까지 넣을 수 있어요"), 빈 칸(src 없음)은 화면이 저장 전에 빼므로 서버는 거절한다.
- 글 저장 때 `VideoPostLinker`(사진의 `ImagePostLinker`와 같은 방식)가 확인한다: 내가 올렸고, `READY`이고, 다른 글에 쓰이지 않은 영상만("올린 적 없는 영상이 들어 있어요" / "영상 변환이 끝나지 않았어요"). 본문에서 빠진 영상은 연결을 끊는다.
- 글을 지우면 그 글의 영상 파일과 행을 지운다.
- 쓰이지 않은 영상(`post_id is null`)은 만든 지 24시간이 지나면 지금의 정리 작업(매일 04:00)이 지운다. `FAILED` 행도 같은 규칙.

### 4.5 화면 쪽 구현 메모

- 영상 칸은 Tiptap 노드 `video`(블록, 원자 노드)와 React NodeView. 저장되는 속성은 `src` 하나이고, 올리는 중·변환 중 상태는 편집기 안에서만 쓰는 속성(`uploadId`, 저장 안 됨)으로 들고 있다가 완료되면 `src`를 채운다.
- 사진 칸은 같은 NodeView 틀에 `kind="image"`로 쓰고, 사진이 올라가면 칸을 지금의 `image` 노드로 바꾼다.
- `/` 메뉴는 Tiptap 제안 기능(`@tiptap/suggestion`)으로 만든다.
- 올리는 진행률은 `XMLHttpRequest`의 업로드 이벤트로 받는다(fetch는 업로드 진행률이 없다). CSRF 머리글은 지금 API 클라이언트와 같은 방식.
- 변환 진행률은 `GET /api/videos/{id}/status`를 1초마다 부르고, `READY`·`FAILED`가 되면 멈춘다. 칸이 지워지면 멈춘다.

## 5. 운영

- 백엔드 이미지(`backend/Dockerfile` 실행 단계)에 `ffmpeg`를 apt로 설치한다(`--no-install-recommends`).
- `compose.prod.yaml`의 `backend` 메모리 한도 1200m → **1500m**, `JAVA_TOOL_OPTIONS`의 `MaxRAMPercentage` 70 → **50**(힙 약 750MB, 나머지는 ffmpeg 몫). 서버 전체 메모리 1.9GB + 스왑 2GB 안에서 동작한다.
- Caddy는 요청 크기 제한이 없어 바꿀 것이 없다. 업로드가 길어질 수 있어 백엔드 연결 시간 제한도 기본값(제한 없음) 그대로.
- 로컬 개발: 개발자 컴퓨터에 ffmpeg가 없을 수 있으므로 `app.videos.ffmpeg-path`(기본 `ffmpeg`)로 경로를 바꿀 수 있게 하고, 없으면 영상 올리기는 `FAILED`("변환 프로그램이 없어요")로 끝나며 나머지 기능은 그대로 돈다. 테스트는 Testcontainers 이미지 또는 CI에 설치한 ffmpeg를 쓴다(계획에서 정함).

## 6. 테스트

**서버**
- 변환: 테스트가 ffmpeg로 만든 짧은 샘플(예: 1920×1080, 60fps, 소리 있음, 40초)을 올려 `READY`까지 기다린 뒤, 결과가 1280×720, 24fps, 소리 없음, 30초 이하, `truncated=true`인지 `ffprobe`로 확인한다. 진행률이 0→100으로 늘어나는지.
- 판별: 영상이 아닌 파일은 `VIDEO_UNSUPPORTED`, 200MB 초과는 `VIDEO_TOO_LARGE`.
- 권한: 남의 영상 상태 조회는 404 `VIDEO_NOT_FOUND`(있는지조차 알리지 않음), 남의 영상·`PROCESSING` 영상을 본문에 넣으면 저장 거절, 3개 초과 거절.
- 내려주기: `Range: bytes=0-99` 요청에 206과 100바이트.
- 정리: 24시간 지난 쓰이지 않은 영상 삭제, 글 삭제 때 영상 삭제, 시작 시 `PROCESSING` → `FAILED`.

**화면**
- `/` 메뉴: `/`로 열림, `v`로 영상만 남음, Enter로 칸 생성·친 글자 삭제, Esc로 닫힘.
- 영상 칸: 단계별 문구(비어 있음·올리는 중·변환 중·완료·실패), 잘못된 파일·크기·개수 안내.
- 등록 잠금: 변환 중이면 등록 버튼이 잠기고 안내가 보임. 빈 칸은 저장 내용에서 빠짐.
- 글 보기: `video` 노드가 `muted loop playsinline`으로 그려지고 누르면 멈춤 표시.
- `extensions.test.ts`에 `video` 노드 추가.

**브라우저**
- 로컬에서 실제 게임 영상(30초 넘는 것)을 넣어 끝까지 확인하고, 휴대폰 크기 화면에서 칸 누르기로 고르기가 되는지 확인한다.

## 7. 위험과 주의

- 2 vCPU 서버에서 30초 클립 변환은 약 20~40초 예상. 여럿이 동시에 올리면 줄을 서서 기다린다.
- 원본 200MB를 올리는 데 집 인터넷에서 수십 초가 걸릴 수 있다. 올리는 중 진행률로 안내한다.
- Lightsail 월 전송량 3TB 안에서 충분하다(클립 5MB × 하루 수백 번 재생 수준).
- ffmpeg 설치로 백엔드 이미지가 약 100~200MB 커진다. 첫 배포가 조금 느려진다.
