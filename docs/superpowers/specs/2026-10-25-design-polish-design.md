# 디자인 다듬기 설계 — 칼바람 나락의 밤

- 작성일: 2026-10-25
- 상태: 사용자가 목업을 승인하고, 남은 결정은 Claude가 정해 나중에 보고하기로 함
- 목업(같은 폴더, 브라우저로 열면 그대로 보인다)
  - `2026-10-25-design-polish-mockup-main.html` — 디자인 규칙, 메인 글 목록(PC·휴대폰), 글 상세
  - `2026-10-25-design-polish-mockup-screens.html` — 증강·챔피언 탭, 모아보기, 글쓰기, 프로필, 프로필 수정, 작은 상태 화면, 휴대폰
- 목업과 이 문서가 다르면 이 문서가 맞다.

## 1. 목적

지금 화면은 어두운 남색에 틀만 잡혀 있다. 이걸 **리그 오브 레전드 칼바람 나락 분위기**로 다듬는다. 바탕은 연한 하늘색(서리 낀 얼음), 장식은 금색, 포인트는 청록이다. 머리말과 화면 머리 띠만 밤하늘 남색으로 둬서 게임 클라이언트 느낌을 낸다.

크기·위치·모서리는 모두 정해진 규칙(3장)에서 나오고, 중요한 것만 강조하고 나머지는 간략하게 보인다.

**성공 기준**
- 모든 화면(지금 있는 21개 + 닉네임 정하기)이 같은 색·글꼴·간격 규칙을 쓴다. 밝은 하늘색 바탕이다.
- 글 목록 한 줄에서 "작성자 사진·이름 + 제목"이 가장 먼저 보이고, 태그·패치·시간·댓글 수는 작게 보인다.
- 버튼은 쓰임에 따라 48/44/40px 세 크기 중 하나다. 휴대폰에서 손가락으로 누르는 버튼은 모두 44px 이상이다.
- 챔피언·증강은 어디서나 "아이콘 + 이름" 한 덩어리 태그로 보인다.
- 패치는 "26.21 버전" 묶음으로 보이고, 지금 패치면 "최신" 표시가 붙는다.
- PC에서 본문 폭이 1120px로 넓어져 양옆이 비지 않는다. 휴대폰(가로 390px)에서 가로 스크롤이 생기지 않는다.
- 기능은 그대로다. 아래 7장에 적은 작은 변화만 있다.
- 화면 문구는 지금 문구를 그대로 쓴다. 목업의 예시 문구(예: "반가워요!", "비공개 프로필이에요")는 모양을 보여주려던 것이고, 새로 생기는 요소(버튼 이름 등)만 새 문구를 쓴다.

## 2. 범위

**포함**: 모든 화면의 색·글꼴·크기·배치, 공통 부품 정리(4장), 7장의 작은 기능 변화, 프로필의 "받은 추천" 숫자(서버 포함).

**제외**: 어두운 화면(다크 모드) — 밝은 화면 하나만 만든다. 화면 문구 번역. 증강 카드(게임 카드 그림) 자체의 모양 — 그대로 두고 밤하늘 바탕 위에 올린다. 실제 칼바람 나락 게임 그림을 배경으로 쓰는 일. 자동 저장 등 새 기능. 글 내용·API 응답 형식 변경(받은 추천 제외).

### 3.2 글꼴

- 제목 글꼴 **Hahmlet**(700): 로고, 화면 제목(28), 글 상세 제목, 펼침 영역 이름, 프로필 숫자, 빈 화면 제목. 각진 세리프라 게임 느낌을 낸다. 화면 하나에 한두 군데만 쓴다.
- 본문 글꼴 **Noto Serif KR**(400·500·600·700): 나머지 전부(입력칸·버튼·업데이트 중 안내 포함). 처음에는 Noto Sans KR이었는데, 발더스 게이트 3 설명 같은 명조가 읽기 좋다는 사용자 의견으로 2026-10-26에 바꿨다.
- 둘 다 Google Fonts에서 받는다. 받기 전에는 `Malgun Gothic`, `Apple SD Gothic Neo` 순으로 보인다.
- 숫자가 줄 맞춰 바뀌는 곳(추천 수, 페이지 번호, 개수)은 숫자 폭을 고정한다(`tabular-nums`).

### 3.3 간격과 폭

- 간격은 4px의 배수만 쓴다. 요소 사이 8, 묶음 안 16, 묶음 사이 24, 구역 사이 48.
- 본문 폭: 머리말과 목록 화면 1120px(지금 768px). 글 상세·글쓰기·프로필 수정은 768px. 글 본문 글자는 한 줄 약 40자(40em)를 넘지 않는다.
- 화면 양옆 여백: PC 24px, 휴대폰 12~16px.

### 3.4 글자 크기 (5단계)

| 크기 | 쓰는 곳 |
|---|---|
| 28 | 화면 제목, 글 상세 제목, 프로필 닉네임, 모아보기 이름, 프로필 숫자 |
| 20 | 목록의 글 제목, 구역 제목(댓글), 펼침 영역 이름, 빈 화면 제목 |
| 17 | 글 본문, 편집기 글자, 제목 입력칸, 등급 묶음 이름, 펼침 안 소제목 |
| 15 | 버튼, 탭, 메뉴, 입력칸, 글 상세 작성자 이름, 큰 태그, 한 줄 글 목록의 제목 |

예외: 패치 묶음 안 "최신" 표시와 잔디의 달 이름은 11px, 휴대폰 목록 제목은 17px, 휴대폰 목록 작성자 이름은 12px, 휴대폰 글 상세 제목은 20px(100자 제목이 28px이면 화면 절반을 차지해서).

| 높이 | 버튼 | 이유 |

| 56 | 휴대폰 글쓰기(떠 있는 버튼) | 엄지로 누르는 화면의 주인공 |
| 48 | 추천, 스크랩, 글 상세 태그, 입력칸 | 글을 읽고 바로 누르는 버튼. 입력칸은 버튼보다 커서 누르기 쉽다 |

### 3.6 모서리

**담는 것은 각지게, 누르는 것은 둥글게** — 모양만 봐도 누를 수 있는지 알 수 있다.

| 반경 | 쓰는 곳 |
|---|---|
| 0 | 글 카드, 글 상세 틀, 펼침 영역, 폼 틀, 머리말, 머리 띠, 등급 묶음, 메뉴 상자, 알림 |
| 4 | 증강 아이콘, 패치 묶음 |
| 8 | 버튼, 태그, 정렬, 페이지 번호, 입력칸, 편집기, 증강·챔피언 칸 |
| 원 | 사람 프로필 사진, 챔피언 얼굴, 공개 설정 스위치 |

모서리를 비스듬히 깎는 모양은 쓰지 않는다.

### 3.7 강조 3단계

- **강하게**: 작성자(사진 + 이름) + 글 제목, 글쓰기 버튼, 글 상세의 추천 버튼.
- **보통**: 추천 수(금색), 정렬, 메뉴, 최신 패치 표시, 글 상세의 태그.
- **간략하게**: 목록의 태그(28px), 패치·시간·댓글 수(13px 회색). "추천" 같은 이름표 글자는 빼고 숫자와 기호만 둔다.

### 3.8 장식

- 머리말·머리 띠: night → night-2 그라데이션, 아래 금색 1px 선(머리말은 그 아래 2px 띄우고 반투명 금색 한 줄 더).
- **금색 모서리 장식**: 왼쪽 위·오른쪽 아래에 2px 금색 ㄱ자(12~16px). 추천이 1개 이상인 글 카드, 글 상세 틀, 펼침 영역에만 붙는다. 인기 글이 바로 눈에 띄게 하는 표시라 다른 곳에는 쓰지 않는다.
- 로고 앞 마름모(청록 그라데이션 + 금색 테두리), 빈 화면의 금색 마름모.
- 사람 프로필 사진·챔피언 얼굴은 금색 테두리 1px(바탕과 2px 띄움).

## 5. 화면

### 5.1 메인 글 목록 (`/`)

- 화면 제목 "전체 글"(28, 제목 글꼴) 옆에 "글 n개"(13 회색). 그 아래 정렬.
- 글 카드 한 줄은 3칸이다.
  - 왼쪽 64px: 작성자 사진 40px, 그 아래 이름(13, 굵기 500, 길면 말줄임). 누르면 그 사람 프로필.
  - 가운데: 제목(20 굵게, 남색) → 태그 줄(작은 태그, 위 12px 띄움) → 패치 묶음 · 시간 · "댓글 n"(13 회색, 위 8px).
  - 오른쪽 48px: 금색 삼각형 + 추천 수. 추천이 있으면 gold-deep, 0이면 흐린 회색.
- 카드 사이 8px. 추천 1개 이상인 카드에만 금색 모서리 장식.
- 페이지 번호는 목록 아래 가운데.

### 5.2 글 상세 (`/posts/:id`)

- "‹ 목록으로"(13 회색) 아래 금색 모서리 틀(안쪽 여백 32).
- 제목 28(제목 글꼴) → 사진 32 · 이름(15 굵게) · 시간 · 패치 묶음 … 오른쪽 끝 수정·삭제(글자 버튼, 글쓴이·관리자만).
- 본문 17px, 줄 간격 1.75.
- 태그 줄: 큰 태그(48, 누르면 모아보기).
- 추천(금색 48, 최소 폭 144, "▲ 추천 n")과 스크랩(테두리 48) 가운데 나란히.
- 댓글: "댓글 n"(20, 숫자 금색) → 입력칸 + 등록(청록, 입력칸 높이에 맞춤) → 댓글마다 사진 36 · 이름 15 굵게 · 시간 13 · 내용 15.

### 5.3 증강 탭 (`/augments`)

## 6. 반응형 기준

- 머리말은 1024px 이상에서 한 줄(64px)이고, 그보다 좁으면(휴대폰·태블릿) 5.11의 두 줄 머리말과 떠 있는 글쓰기 버튼을 쓴다. 로그인 전 머리말 한 줄에 필요한 폭이 약 850px라 640~1024px에서 넘치거나 메뉴 글자가 세로로 쪼개졌기 때문이다(검토에서 발견).
- 그 밖의 화면(글 카드·격자·폼)은 640px을 기준으로 휴대폰 모양과 PC 모양이 바뀐다.
- 격자는 칸 최소 폭으로 자동으로 줄 수가 정해진다(증강·챔피언 칸 104px, 휴대폰 3칸 고정).

## 7. 작은 기능 변화

1. **글 목록**: 작성자 사진과 이름을 왼쪽 칸에, 추천 수를 오른쪽 끝으로 옮긴다. 챔피언·증강은 아이콘만이 아니라 이름이 붙은 태그로 보인다.
2. **최신 패치 표시**: 패치 묶음이 지금 패치(`GET /api/patches`의 `current`)와 같으면 "최신"을 붙인다. 목록·글 상세·글쓰기에 같은 부품을 쓴다.
3. **증강·챔피언 칸**에서 글 수를 뺀다. 「글 많은 순」 정렬은 남긴다.
4. **글쓰기 버튼**은 로그인 전에도 머리말에 보인다. 누르면 지금처럼 "글을 쓰려면 로그인이 필요해요" 화면이 나온다. (휴대폰은 떠 있는 버튼.)
5. **로그인 버튼**에 디스코드 로고를 넣는다. 로그인하면 그 자리에 내 사진(이름 글자는 PC에서도 빼고 메뉴 안에 둔다).
6. **내 메뉴**에 "프로필 수정"을 더한다.
7. **프로필 사진이 없으면** 닉네임 첫 글자를 보여준다(지금은 보라색 원).
8. **프로필 숫자**: 작성한 글 · 작성한 댓글 · **받은 추천**. 가입일은 머리 띠에 한 번만 보인다. 받은 추천은 그 사람이 쓴 글들이 받은 추천 수의 합이다. 서버 프로필 응답 `stats`에 `receivedLikeCount`를 더한다(비공개 프로필이면 다른 숫자처럼 숨긴다). 스크랩 수는 탭 이름 옆에 그대로 보인다.
9. **글쓰기·글 수정의 등록·취소**를 화면 아래 고정 띠로 옮긴다.
10. **알림** 위치를 아래 가운데로 옮긴다.
11. **패치 고르기**의 글자를 "26.21 버전"으로 바꾸고 옆에 패치 묶음을 보여준다(고를 수 있는 값과 기본값은 지금과 같다).

## 8. 기술 결정

- **색·크기 규칙은 Tailwind 4의 `@theme`**(`index.css`)에 이름으로 둔다(`--color-night`, `--color-gold` …, `--radius-touch: 8px`, `--radius-mark: 4px`). 화면 코드는 `bg-night`, `rounded-touch`처럼 이름만 쓴다. 숫자를 화면마다 흩어 쓰지 않아야 나중에 바꾸기 쉽다.
- **글꼴**은 `index.html`에 Google Fonts `<link>`(Hahmlet 700, Noto Sans KR 400·500·700, `display=swap`)를 넣는다. 지금 `index.css`에 이름만 있고 받지 않는 `Pretendard`는 뺀다.
- **어두운 색 클래스**(`slate-800` 등)는 모두 새 이름으로 바꾼다. 다크 모드는 만들지 않는다.
- **공통 부품**은 `components/ui/`에 모은다: `Button`, `TagChip`(champion/augment, size sm·md·lg, 링크/✕), `VersionChip`, `Segmented`(지금 `SortPills` 대체), `SearchInput`, `CornerFrame`(금색 모서리), `HeroBand`, `EmptyState`. 지금 있는 `Avatar`(첫 글자 대체 추가), `Pagination`, `Toast`, `Header`는 자리에서 고친다. 부품마다 한 가지 일만 한다.
- **글 카드**(`PostListItem`)는 일반·한 줄(compact) 두 모양을 유지하되 5.1과 4장 "한 줄 글 목록"대로 다시 짠다.
- **최신 패치**는 `VersionChip`이 `usePatches()`의 `current`를 읽는다(이미 캐시되는 요청이라 추가 부담 없음).
- **증강 카드**(`components/augment/AugmentCard*`)는 손대지 않고, 펼침 영역에서 밤하늘 상자로 감싸기만 한다.
- **증강 아이콘 테두리**: 48px 이상(탭 칸, 펼침 머리, 모아보기 머리 띠)은 지금처럼 게임 테두리 그림(`frame="image"`)을 쓴다. 목업의 단색 테두리보다 게임 느낌이 강하고 이미 있는 그림이다. 작은 태그 안 아이콘은 등급색 선 + 남색 바탕 + 4px 모서리.
- **받은 추천**: `ProfileService`에서 그 사용자 글의 `like_count` 합을 한 번의 쿼리로 센다. DB 변경 없음.

## 9. 테스트와 확인

- 부품마다 동작 테스트를 먼저 쓴다: `VersionChip`(지금 패치면 "최신", 아니면 없음), `TagChip`(이름이 보이고 lg는 모아보기 링크, ✕는 빼기), `Avatar`(사진 없으면 첫 글자), 글 카드(작성자 이름이 사진 칸에, 추천 수, 금색 모서리는 추천 1개 이상만), 증강 칸(글 수가 없음), 머리말(로그인 전 글쓰기 버튼, 디스코드 버튼, 내 메뉴의 프로필 수정), 휴대폰 떠 있는 글쓰기 버튼, 글쓰기 고정 띠.
- 서버: 프로필 `receivedLikeCount`(여러 글의 추천 합, 비공개면 숨김) 테스트.
- 기존 테스트 중 바뀐 모양(문구 "추천" 이름표, 칸의 "글 n개" 등)을 확인하던 것은 새 규칙에 맞게 고친다.
- 화면 확인: 끝나면 화면 모음과 같은 방법(PC 1280, 휴대폰 390, 개발용 예시 자료)으로 모든 화면을 다시 찍어 목업과 나란히 비교하고, 사용자에게 화면 모음 페이지로 보여준다. 휴대폰 폭에서 가로 스크롤이 없는지 확인한다.
- `npm test`, `npm run build`, `npm run lint`, `./gradlew test` 모두 통과.

## 10. 결정 기록

- 분위기: 칼바람 나락. 처음 제안한 어두운 화면 대신 사용자가 **연한 하늘색 바탕**을 골랐다.
- 진하기 시안 A(서리)·B(얼음 다리)·C(나락의 밤) 중 **C**. 머리말만 밤하늘, 본문은 하늘색.
- 처음 시안의 비스듬히 깎은 모서리는 빼고, 모두 직각으로 했다가 "모두 각지니 별로"라는 의견에 따라 **담는 것은 각지게, 누르는 것은 둥글게**로 정했다.
- 태그는 아이콘과 이름을 한 덩어리로(아이콘 순서와 이름 순서를 맞춰 읽지 않게).
- 패치는 "26.21 버전" 묶음, 지금 패치면 "최신".
- 글 목록은 제목을 키우고 나머지를 줄이며, 작성자 이름은 프로필 사진 바로 아래.
- 증강·챔피언 칸의 글 수는 쓸모가 적어 뺐다.
- 프로필의 받은 추천은 나머지 화면 시안에 제안으로 넣었고, 사용자가 "이 시안대로"로 승인했다.
