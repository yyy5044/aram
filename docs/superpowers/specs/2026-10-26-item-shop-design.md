# 아이템 탭 상점 구조 설계

- 작성일: 2026-10-26
- 상태: 사용자 검토 대기
- 기반: `2026-10-26-item-tab-design.md`(아이템 데이터·설명 계산·`@` 아이템), `2026-10-25-design-polish-design.md`(색·글꼴·크기 규칙)
- 바꾸는 것: `2026-10-26-item-tab-design.md`의 아이템 탭 화면(단계 묶음 펼치기)과 아이템 태그(글 태그 칸·글 목록·`/items/:itemId`·글 수)

## 1. 목적

지금 아이템 탭은 단계 묶음을 하나씩 펼치는 방식이라 알아보기 힘들다. 아이템은 증강(프리즘·골드·실버)보다 나눌 기준이 많아서, 게임 상점처럼 **능력치로 걸러내고 단계별로 한눈에 보는** 구조가 맞다. 그리고 아이템은 글의 태그가 아니다(사용자 결정). 글 태그는 증강·챔피언만이고, 아이템 탭은 두 용도로만 쓴다.

1. 증강 칼바람 상점에 무엇이 있는지 **위키처럼 찾아보기**
2. 글 본문에 "이 아이템이 좋다"고 **쓰기**(본문 `@` 아이템과 설명 상자)

**성공 기준**
- 아이템 탭에서 능력치 버튼을 눌러 원하는 아이템을 좁히고, 단계별 줄에서 바로 찾는다(접었다 펼치지 않는다).
- 아이템을 고르면 조합 나무·상위 아이템·설명이 한 곳에 나오고, 나무나 상위 아이템을 눌러 옮겨 다닌다.
- 휴대폰에서도 같은 일을 할 수 있다(설명은 아래서 올라오는 창).
- 글쓰기·글 목록·글 화면 어디에도 아이템 태그가 없다. 본문 `@` 아이템은 그대로다.

## 2. 범위

**포함**: 아이템 능력치 분류 저장·동기화, 아이템 탭 새 화면(걸러내기·검색·단계별 줄·고른 아이템 칸·휴대폰 아래 창), 고른 아이템 주소(`?item=`), 아이템 태그 기능 제거(서버·화면·DB).

**제외**: 챔피언별 추천 아이템, 아이템 비교, 능력치 수치로 정렬, 상점 "구매"·골드 계산, 본문 아이템 박스를 누르면 아이템 탭으로 가기(지금처럼 아무 데도 안 감, 사용자 결정 유지), 협곡 아이템.

## 3. 사용자 결정

| 질문 | 결정 |
|---|---|
| 본문 `@` 아이템과 설명 상자 | 그대로 둔다. 다만 고른 아이템을 태그 칸에 더하지 않는다 |
| 상점에서 따라 할 부분 | 능력치 걸러내기, 단계별 줄, 조합 나무, 상위 아이템 줄 모두 |
| 휴대폰에서 설명 위치 | 아래서 올라오는 창 |
| 디자인 | 레이아웃과 찾는 구조는 롤 상점, 색·글꼴·모서리는 우리 사이트(`index.css` `@theme`) |

## 4. 데이터

### 4.1 능력치 분류

게임 자료 `items.cdtb.bin.json`의 `ItemData.mCategories`(문자열 목록)를 아이템마다 그대로 저장한다. 16.21 기준 살 수 있는 192개 중 191개가 하나 이상 가지고 있다(없는 1개는 걸러내기를 켜면 안 보이고 "모든 아이템"에서만 보인다).

새 Flyway `V14__item_categories.sql`:

```sql
alter table items add column categories text[] not null default '{}';
update game_data_state set current_cdragon_version = null;  -- 다음 시작 때 전체 재동기화로 채움
drop table post_items;
```

- `current_cdragon_version`만 비운다. 동기화가 "CommunityDragon 버전이 바뀜"으로 보고 전체를 다시 받는다(`GameDataSyncService`의 `cdragonChanged`). `current_ddragon_version`은 그대로라 그동안 챔피언 그림·아이템 아이콘 주소가 비지 않는다(V12와 같은 이유).
- `ItemCatalog`가 `mCategories`를 읽어 `Item.categories`(`List<String>`)에 넣는다. 저장 순서는 자료 순서 그대로.
- `post_items`는 지운다. 아이템 탭·아이템 태그는 아직 운영에 올라가지 않았으므로 운영 데이터 손실이 없다(로컬 시험 글의 아이템 태그만 사라진다).

### 4.2 API

- `GET /api/items`의 `ItemDto`에 `categories: string[]`를 더한다. 화면은 이 목록 하나로 걸러내기·검색·단계별 줄·조합 나무·상위 아이템을 모두 만든다(`fromIds`·`intoIds`는 이미 있음). 지금처럼 사용 중(`active`)인 아이템만 탭에 보인다.
- `GET /api/items/{id}?lang=`(설명)은 그대로 쓴다.
- 빠지는 것: `GET /api/posts?item=`, 글 요청 `itemIds`, 글 목록·글 화면 응답의 `items`, `GET /api/tag-counts`의 `items`.

## 5. 능력치 걸러내기

버튼 15개(위에서 아래 순서). 한 버튼은 아래 분류 중 **하나라도** 가진 아이템과 맞는다.

| 버튼 | `mCategories` |
|---|---|
| 모든 아이템 | (걸러내기 해제) |
| 공격력 | `Damage` |
| 치명타 | `CriticalStrike` |
| 공격 속도 | `AttackSpeed` |
| 적중 시 효과 | `OnHit` |
| 방어구 관통력 | `ArmorPenetration` |
| 흡혈 | `LifeSteal`, `SpellVamp` |
| 주문력 | `SpellDamage` |
| 마나 | `Mana`, `ManaRegen` |
| 마법 관통력 | `MagicPenetration` |
| 체력 | `Health`, `HealthRegen` |
| 방어력 | `Armor` |
| 마법 저항력 | `SpellBlock`, `MagicResist` |
| 스킬 가속 | `AbilityHaste`, `CooldownReduction` |
| 이동 속도 | `NonbootsMovement`, `Boots` |

- 여러 버튼을 켜면 **켠 버튼 모두**와 맞는 아이템만 남는다(예: 공격력 + 치명타).
- 켠 버튼을 다시 누르면 꺼진다. "모든 아이템"을 누르면 모두 꺼진다. 아무것도 안 켜졌을 때 "모든 아이템"이 켜진 모양이다.
- 표에 없는 분류(`Active`, `Tenacity`, `Consumable`, `Lane`, `Aura`, `Slow`, `Jungle`, `Vision`, `GoldPer`, `Stealth` 등)는 걸러내기에 쓰지 않는다.
- 이 표는 화면 `lib/itemStats.ts` 한 곳에 둔다.
- 켠 버튼은 주소에 남기지 않는다(새로고침하면 풀림). 고른 아이템만 주소에 남긴다.

## 6. 화면

### 6.1 넓은 화면(1024px 이상)

세 칸: 왼쪽 능력치(약 176px) · 가운데 아이템 줄(남는 폭) · 오른쪽 고른 아이템(약 340px, 스크롤해도 화면 위쪽에 붙어 있음).

- 머리: 화면 제목 "아이템"(28, 제목 글꼴) 옆에 "아이템 n개"(13 회색, 걸러낸 뒤 개수). "글 n개"·정렬 버튼은 없다.
- 능력치 칸: 버튼은 글자만(아이콘 없음), 높이 36, 켜지면 청록 바탕·흰 글자(`buttonClass`의 기존 종류를 쓴다).
- 가운데 칸: 맨 위 검색창(지금 아이템 탭과 같은 모양, 초성·띄어쓰기 무시 `lib/tagSearch.ts`). 그 아래 단계별 줄을 이 순서로 모두 펼쳐 둔다.
  1. 증강 칼바람 전용(`AUGMENT_MODE`)
  2. 시작(`STARTER`)
  3. 신발(`BOOTS`)
  4. 기본(`BASIC`)
  5. 서사(`EPIC`)
  6. 전설(`LEGENDARY`)
- 줄 머리는 단계 이름(15 굵게)과 개수(13 회색). 줄 안 아이템은 총가격이 싼 것부터, 같으면 이름 가나다순.
- 아이템 칸: 아이콘 48×48(모서리 4), 아래에 가격(13 금색). 이름은 마우스를 올리면(`title`)과 화면 읽기용 이름으로 준다. 고른 아이템은 금색 테두리 2px.
- 맞는 아이템이 없는 줄은 숨긴다. 모두 없으면 가운데에 "조건에 맞는 아이템이 없어요"와 「조건 지우기」(검색어·능력치 모두 해제).
- 오른쪽 칸(위에서 아래):
  1. **조합 나무**: 맨 위 고른 아이템(아이콘 48), 아래로 재료(`fromIds` 순서, 같은 재료가 두 번이면 두 칸), 재료의 재료까지 끝까지. 칸마다 아이콘 아래 총가격. 부모와 자식은 가는 선(`border-line`)으로 잇는다. 나무의 아이템을 누르면 그 아이템을 고른다.
  2. **만들 수 있는 아이템**: `intoIds` 중 사용 중인 아이템을 가격순 한 줄(아이콘 40, 넘치면 줄바꿈). 없으면 이 부분을 숨긴다. 누르면 그 아이템을 고른다.
  3. **설명**: 이름(20 굵게), "3000 골드 · 전설"(13 회색), 선택 언어 설명(지금 `ItemTooltipBody`와 같은 서식·색 표식).
  - 아무것도 안 골랐으면 "아이템을 고르면 조합과 설명이 나와요"(15 회색) 한 줄.
  - 재료나 상위 아이템이 사용 중이 아니면(상점에 없음) 아이콘을 흐리게(투명도 50%) 보여주고 누를 수 없다.

### 6.2 중간 화면(768~1023px)

두 칸: 가운데 아이템 줄 · 오른쪽 고른 아이템. 능력치 버튼은 검색창 아래 가로 한 줄(넘치면 줄바꿈).

### 6.3 휴대폰(768px 미만)

- 한 칸. 능력치 버튼은 검색창 아래 가로 한 줄로 밀어서 본다(줄바꿈 없음, 가로 스크롤).
- 아이템을 누르면 **아래서 올라오는 창**(화면 높이의 최대 85%, 위쪽 모서리 8, 안에서 스크롤)에 오른쪽 칸 내용이 나온다. 창 위에 닫기 버튼(44×44, "닫기"). 뒤 화면은 어둡게 덮고, 덮개를 누르거나 Esc를 누르거나 닫기 버튼으로 닫힌다. 닫으면 보던 스크롤 위치 그대로다.
- 창 안에서 나무·상위 아이템을 누르면 창 안 내용만 바뀐다.
- 창이 열린 동안 뒤 화면은 스크롤되지 않는다. 열리면 초점이 닫기 버튼으로 가고, 닫히면 누른 아이템 칸으로 돌아온다.

### 6.4 주소

- 고른 아이템은 `/items?item=3084`. 주소로 바로 열면 그 아이템이 골라져 있고, 휴대폰이면 창이 열린 채로 시작한다.
- 다른 아이템을 고르면 주소를 바꾸되 뒤로 가기 기록은 쌓지 않는다(`replace`). 창을 닫거나 고른 것을 풀면 `item`을 지운다.
- 없거나 사용 중이 아닌 번호면 아무것도 고르지 않은 상태로 보여주고 주소에서 `item`을 지운다.
- 옛 주소 `?open=`과 `/items/:itemId`는 없앤다(아직 운영에 없던 주소).

### 6.5 화면 언어

설명은 머리말 언어 설정을 따른다(지금 아이템 설명 상자와 같음). 버튼·줄 이름 등 화면 문구는 한국어.

## 7. 아이템 태그 제거

**서버**
- `PostRequest.itemIds`, `Post.items`, `PostRepository`의 아이템 태그 조회(`findItemTags`·`countByItem` 등), `PostListService`의 `item` 걸러내기와 목록 `items`, `PostDetailResponse.items`, `TagCountsResponse.items`를 없앤다.
- 글 저장 요청에 `itemIds`가 와도 무시된다(모르는 칸).
- 본문 `tagMention`의 `kind: item` 검사(`PostContentValidator`)와 실제 아이템이 있는지 확인(`PostService.requireMentionedTagsExist`)은 그대로 둔다.

**화면**
- 글쓰기(`WritePage`): 아이템 태그 칸을 없앤다. `@` 메뉴에서 아이템을 골라도 태그 칸에 더하지 않는다(챔피언·증강은 지금처럼 더함).
- 글 목록 한 줄·글 화면: 아이템 태그 칩을 없앤다.
- `TagPage`의 아이템 종류와 `/items/:itemId` 길, `TagPostsPanel`의 아이템 종류, `TagPicker`·`TagChip`·`tagPath`의 아이템 종류를 없앤다.
- 남기는 것: `@` 메뉴 아이템 후보(`lib/mentionCandidates.ts`), 본문 아이템 박스(`TagMentionChip`)와 설명 상자(`components/item/ItemTooltip.tsx`).

## 8. 오류·예외

| 경우 | 처리 |
|---|---|
| 아이템 자료를 못 받음(빈 목록) | "아직 아이템 정보를 받아오지 못했어요"(챔피언 탭과 같은 문구 방식) |
| 설명 불러오기 실패 | 오른쪽 칸 설명 자리에 "설명을 불러오지 못했어요". 나무·상위 아이템은 목록 자료로 그대로 보인다 |
| 조합 나무의 재료가 목록에 없음(옛 번호) | 그 칸을 빈 회색 칸으로 그리고 누를 수 없다 |
| 업데이트 중(503) | 다른 화면처럼 서버 문장을 그대로 보여준다 |

## 9. 테스트

**서버**
- `ItemCatalog`가 `mCategories`를 `categories`로 읽는다(없으면 빈 목록).
- `GET /api/items`에 `categories`가 들어 있다.
- V14 뒤 시작하면 전체 재동기화가 일어난다(`current_cdragon_version`이 비어 있으면 `cdragonChanged`).
- 글 저장 요청에 `itemIds`를 넣어도 저장되고 무시된다. 본문 `@` 아이템은 지금처럼 저장되고, 없는 아이템 번호면 거절된다.
- 글 목록·글 화면·`tag-counts` 응답에 `items`가 없다. `GET /api/posts?item=…`은 걸러내지 않는다(모르는 매개변수).

**화면**(Vitest, StrictMode)
- `lib/itemStats.ts`: 버튼별 맞는 분류, 여러 버튼은 모두 맞아야 함.
- 아이템 탭: 단계별 줄 순서·가격순, 능력치 버튼 켜기/끄기/"모든 아이템", 검색(초성)과 함께 쓰기, 빈 결과와 「조건 지우기」, 아이템을 누르면 오른쪽 칸과 주소 `?item=`, 나무·상위 아이템 누르면 바뀜, `?item=`으로 시작, 없는 번호면 `item` 지움, 사용 중 아닌 재료는 누를 수 없음.
- 휴대폰 폭: 누르면 아래 창이 열리고 닫기·Esc·덮개로 닫힘, 초점 이동.
- 글쓰기: 아이템 태그 칸이 없고 `@` 아이템을 골라도 태그 칸이 늘지 않음. 글 목록·글 화면에 아이템 칩이 없음.

**브라우저 확인**: 넓은 화면·중간·휴대폰 폭에서 걸러내기·검색·조합 나무·상위 아이템·아래 창을 직접 눌러 보고 화면 사진을 남긴다.
