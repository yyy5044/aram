# 증강 카드 설계

- 작성일: 2026-10-24
- 상태: 사용자 검토 대기
- 기반: `2026-10-24-tag-browse-design.md` (증강 탭의 펼침 영역을 바꾼다)
- 목업: `2026-10-24-augment-card-mockup.html` (같은 폴더, 브라우저로 열면 CommunityDragon 이미지를 받아 그린다)

## 1. 목적

증강 탭에서 증강을 누르면 지금은 글 목록만 펼쳐진다. 이걸 **게임 속 증강 카드**를 중심으로 바꾼다. 카드에는 숫자가 채워진 긴 설명이 들어가고, 영어 원문 카드와 선택 언어(지금은 한국어) 카드를 나란히 보여 번역 오류를 바로 비교할 수 있게 한다. 글 목록은 그 아래로 작게 내린다.

**성공 기준**
- 증강을 누르면 게임 카드와 닮은 카드가 나온다. 등급(프리즘·골드·실버)에 따라 테두리가 바뀌고, 이름·등급·설명이 보인다.
- 설명에 `@TotalShield@` 같은 자리표시자가 아니라 `150~450 (+최대 체력의 4%)` 같은 실제 수치가 보인다.
- 왼쪽은 영어 원문, 오른쪽은 머리말 언어 설정에서 고른 언어다. 둘이 같으면 한 장만 보인다.
- 카드에 마우스를 올리면 복사 버튼이 나타나고, 누르면 설명이 글자로 복사된다.
- 글 목록은 카드 아래에 한 줄짜리로 보이고, 정렬과 「더 보기」는 그대로 된다.

## 2. 범위

**포함**: 증강 탭 펼침 영역 개편(카드 2장 + 글 목록), 증강 설명 수집(영어·한국어), 설명 속 수치 계산, 머리말 언어 설정(한국어·English, 브라우저에 기억), 증강 상세 API.

**제외**: 화면 문구(버튼·안내문·오류 문장) 번역 — 언어 설정은 이번에 만들지만 화면 문구는 나중 작업이다. 챔피언 탭 변경. 기존 태그 페이지(`/augments/:id`) 변경. 세 번째 언어 추가. AI 번역. 게임이 선택 화면에 쓰는 짧은 설명(숫자 없는 요약) 표시. 로그인한 사용자 계정에 언어 저장.

## 3. 화면

### 3.1 펼침 영역

증강 탭의 칸을 누르면 지금처럼 그 줄 아래로 영역이 펼쳐지고 주소는 `/augments?open=<증강 id>`다. 영역 안은 위에서 아래로:

1. 제목 줄: 지금과 같은 증강 이름 · "프리즘 증강 · 게시글 n개" · 닫기(✕). (정렬 버튼은 글 목록 쪽으로 내려간다.)
2. 카드 줄: 원문 카드와 번역 카드. 각 카드 위에 작은 표지가 있다. 원문 카드 위 "원문 · English", 번역 카드 위 "번역 · 한국어"(언어 설정의 이름). 드롭다운은 여기 두지 않는다(머리말 언어 설정이 담당).
3. 글 목록: "이 증강 글 n개" 제목, 오른쪽에 최신순·추천순, 아래 한 줄짜리 글 목록, 「더 보기 (n개 남음)」.

### 3.2 카드

크기는 폭 300px, 높이 492px(게임 카드 비율 312:512). 구성은 목업과 같다.

- 바탕과 테두리: CommunityDragon의 게임 파일을 그대로 쓴다. 바탕 `augmentcard_bg.png`, 테두리는 등급별 `augmentcard_frame_silver.png` / `_gold.png` / `_prismatic.png` (`assets/ux/cherry/augments/augmentselection/`). 512×512 그림 가운데 312px 폭만 카드이므로, 그림을 492px로 키워 좌우 96px씩 잘라 보인다.
- 아이콘: 증강의 큰 아이콘(`AugmentLargeIconPath`)을 볼트 박힌 팔각형 틀 안에 넣는다. 팔각형 틀은 게임 파일에 없어서 CSS로 그린다.
- 이름: 카드 언어의 이름. 영어 카드는 "Ominous Pact", 한국어 카드는 "불길한 서약".
- 등급 표: 이름 아래 작은 표. 한국어 카드는 "일반" / "골드" / "프리즘", 영어 카드는 "Silver" / "Gold" / "Prismatic". 색은 실버 회색, 골드 금색, 프리즘 보라.
- 설명: 숫자가 채워진 긴 설명(4장 참고). 줄바꿈을 지키고, 게임 표식에 따라 단어 색을 입힌다.

| 표식 | 색 | 예 |
|---|---|---|
| `magicDamage`, `scaleAP` | 파랑 `#49b6ff` | 주문력, 마법 피해 |
| `physicalDamage`, `scaleAD` | 주황 `#ff8c34` | 공격력, 물리 피해 |
| `trueDamage` | 흰색 `#f5f5f5` | 고정 피해 |
| `health`, `scaleHealth`, `healing` | 초록 `#2ecc71` | 체력, 회복 |
| `shield` | 하늘 `#9ad8ff` | 보호막 |
| `speed` | 연노랑 `#e8d58a` | 이동 속도 |
| `omnivamp`, `lifeSteal`, `lifesteal` | 빨강 `#ff5c5c` | 흡혈 |
| `status`, `keyword`, `keywordMajor`, `active`, `passive` | 노랑 `#f1e2a8` | 이동 불가, 기절 |
| `attackSpeed`, `gold` | 금색 `#f0c674` | 공격 속도, 골드 |
| `rules`, `rule` | 회색 기울임 `#8d99ae` | 규칙 설명 줄 |

표에 없는 표식은 색 없이 글자만 보인다. 화면은 표식을 HTML로 그대로 넣지 않고, 아는 표식만 `<span>`으로 바꾼다(본문 편집기의 허용 목록과 같은 원칙).

### 3.3 복사

- 카드에 마우스를 올리면(또는 키보드 초점이 들어오면) 오른쪽 위에 "복사" 버튼이 0.25초 동안 살짝 내려오며 나타난다. 벗어나면 사라진다. 터치 화면에서는 항상 보인다(hover가 없으므로).
- 누르면 그 카드의 **설명만** 글자로 복사한다. 표식은 빼고 줄바꿈은 지킨다. 복사되면 토스트 "복사했어요", 실패하면 "복사하지 못했어요".
- 카드 글은 드래그로도 선택·복사할 수 있다.

### 3.4 머리말 언어 설정

- 머리말 오른쪽, 로그인 버튼(또는 글쓰기 버튼) 왼쪽에 작은 드롭다운. 지구본 표시 + 현재 언어 이름("한국어" / "English").
- 선택지는 한국어(`ko`)와 English(`en`) 둘. 고르면 즉시 반영되고 브라우저(localStorage `lang`)에 기억된다. 처음 방문은 한국어.
- 이번에는 오른쪽 카드만 이 설정을 따른다. 화면 문구는 그대로 한국어다. 나중에 화면 문구 번역이 들어올 때 같은 설정을 읽는다.
- 언어 설정은 앱 전체에서 읽을 수 있는 값(React context)으로 둔다. 카드가 아닌 곳에서도 쓸 수 있어야 하기 때문이다.

### 3.5 같은 언어일 때

선택 언어가 원문 언어(영어)와 같으면 번역 카드를 숨기고 원문 카드 한 장만 가운데에 둔다. 영어 전용 규칙이 아니라 "두 언어가 같으면 숨김"이라는 하나의 규칙이다.

### 3.6 좁은 화면

카드 두 장(300px × 2 + 간격)이 들어가지 않는 폭에서는 위아래로 쌓는다. 원문이 위, 번역이 아래. 카드 크기는 줄이지 않는다.

### 3.7 상태

- 설명을 불러오는 동안: 카드 자리에 "불러오는 중이에요".
- 실패: "잠시 후 다시 시도해주세요".
- 어떤 언어의 설명이 아직 없을 때(첫 동기화 전 등): 그 카드 자리에 "아직 설명이 없어요"라고 쓴 빈 카드 틀.
- 지금 게임에 없는 증강(비활성)은 목록에 안 나오므로 펼칠 수 없다. `?open=`으로 억지로 열어도 지금처럼 무시한다.

## 4. 데이터

### 4.1 원천

모두 CommunityDragon `latest` 기준이고, 지금 증강 목록을 받는 곳과 같다.

| 자료 | 주소 | 쓰는 것 |
|---|---|---|
| 증강 목록 | `game/maps/modespecificdata/kiwi.bin.json` | `NameTra`, `AugmentTooltipTra`, `AugmentLargeIconPath`, `RootSpell`, `AdditionalSpells`, `rarity`, `Enabled` |
| 수치 표 | 같은 파일 안의 `RootSpell`/`AdditionalSpells`가 가리키는 항목 | `mSpell.DataValues`, `mSpell.mSpellCalculations` |
| 영어 문자열 | `game/en_us/data/menu/en_us/lol.stringtable.json` | 이름·설명 |
| 한국어 문자열 | `game/ko_kr/data/menu/en_us/lol.stringtable.json` | 이름·설명 (지금도 받는다) |

문자열 표는 30MB가 넘으므로 지금처럼 필요한 키만 스트리밍으로 골라낸다. 언어마다 한 번씩 받는다.

### 4.2 저장

새 표 `augment_texts`:

| 열 | 뜻 |
|---|---|
| `augment_id` | `augments.id` |
| `locale` | `en` / `ko` (앱 언어 코드. 원천 폴더 이름 `en_us`/`ko_kr`로의 대응은 코드 안 표) |
| `name` | 그 언어 이름 |
| `description` | 수치가 채워진 긴 설명. 게임 표식(`<magicDamage>` 등)과 `<br>`은 그대로 둔다 |
| `updated_at` | 마지막 갱신 시각 |

기본 키는 (`augment_id`, `locale`). 언어를 더할 때는 행만 늘어난다.

`augments`에 `large_icon_path` 열을 더한다(카드용 큰 아이콘). 기존 `name_ko`, `icon_path`는 목록·검색·태그 칩이 계속 쓰므로 그대로 둔다.

마이그레이션 `V8__augment_texts.sql`: 표 생성, 열 추가(기본값은 작은 아이콘 경로를 복사), 그리고 V7처럼 `game_data_state.current_ddragon_version`을 비워 다음 동기화 때 전체를 다시 받게 한다.

### 4.3 설명 만들기

동기화 때 언어마다 아래 순서로 만든다. 입력은 `AugmentTooltipTra`가 가리키는 문자열이다.

1. **문자열 참조 `{{키}}`**: 문자열 표에 그 키가 있으면 그 글로 바꾼다(앞뒤 공백 무시, 한 번만, 바꾼 글 안의 참조는 다시 처리). `{{SpellName}}`, `{{SpellNameOnly}}`는 챔피언마다 다른 스킬 이름이므로 한국어 `[스킬]`, 영어 `[Ability]`로 바꾼다. 그 밖의 참조는 그대로 둔다.
2. **집계 줄 제거**: `@f1@`, `@f2.0@`처럼 `f숫자(.숫자)` 꼴은 게임 중 누적치(입힌 피해 등)다. 그 자리표시자가 든 줄(`<br>`로 나뉜 한 줄) 전체를 지우고, 그래서 끝에 남는 빈 줄도 지운다. `<statTracking>…</statTracking>` 덩어리도 지운다.
3. **수치 `@이름@`, `@이름*100@`**: 4.4 규칙으로 값을 만들어 넣는다. `*100`, `*-100`, `*1000` 같은 꼬리는 값에 곱한다. 못 만든 것은 자리표시자를 **그대로** 둔다(화면에 `@Ult_DamageAmp@`로 보인다). 동기화 끝에 "못 채운 자리표시자 n개"를 로그에 남긴다.
4. **표식 정리**: `<font …>`, `<li>`, `<mainText>`, `<lol>` 등 색 표식이 아닌 것은 벗긴다(안의 글은 남긴다). `<br>`과 3.2 표의 색 표식만 남긴다. `%i:scaleHealShield%` 같은 아이콘 표식은 지운다.
5. 앞뒤 공백·빈 줄을 다듬는다.

### 4.4 수치 계산

`RootSpell`과 `AdditionalSpells`가 가리키는 모든 항목에서 `DataValues`(이름 → 값 7개)와 `mSpellCalculations`(이름 → 계산식)를 모은다. 같은 이름이 여럿이면 `RootSpell` 것이 우선이다.

`@이름@`의 값은:

- `DataValues`에 있으면 그 값. 7칸 값이 모두 같으면 그 수, 다르면 첫 값~마지막 값의 범위(`a~b`).
- `mSpellCalculations`에 있으면 식의 부분들을 아래처럼 글로 만들어 이어 붙인다. 첫 부분은 그대로, 나머지는 `(+…)`로 감싼다. 레벨에 따라 변하는 부분은 `a~b`(1레벨~18레벨).

| 부분 종류 | 글 |
|---|---|
| `NumberCalculationPart` | `mNumber` |
| `NamedDataValueCalculationPart` | 그 `DataValues` 값 |
| `ByCharLevelInterpolationCalculationPart` | `mStartValue~mEndValue` |
| `ByCharLevelBreakpointsCalculationPart` | 1레벨 값 ~ 18레벨 값 (`mInitialBonusPerLevel`과 `mBreakpoints`로 레벨마다 더해 18레벨까지 계산) |
| `StatByCoefficientCalculationPart` | `(+계수×100% 스탯이름)` |
| `StatByNamedDataValueCalculationPart` | `(+값×100% 스탯이름)` |
| `SumOfSubPartsCalculationPart` | 부분들을 ` + `로 |
| `ProductOfSubPartsCalculationPart` | 부분들을 ` × `로 |
| `GameCalculationModified` | 원래 식의 값에 `mMultiplier`를 곱한다(범위면 양 끝에 곱한다) |
| 그 밖(`BuffCounter…`, `AbilityResource…`, 해시 이름 등) | 만들 수 없음 → 자리표시자 유지 |

스탯 이름은 언어별이다(한국어 "주문력", 영어 "AP" 등). 스탯 번호 → 이름 표는 구현할 때 실제 게임 툴팁과 대조해 확정한다. 지금 자료에서 쓰인 번호는 0, 1, 2, 4, 6, 7, 8, 9, 11, 12, 22, 29, 34이고, 0=주문력, 2=공격력, 12=최대 체력은 문맥으로 확인됐다. `mStatFormula`(0 기본, 1 추가, 2 전체)는 2일 때만 "전체", 1일 때 "추가"를 앞에 붙인다. 모르는 번호는 자리표시자 유지.

숫자 표기: 정수는 그대로, 소수는 소수점 한 자리까지(끝 0은 지움). 백분율은 `*100` 꼬리가 붙었을 때만 곱하고, `%` 기호는 원문에 이미 있으니 붙이지 않는다.

검증 기준(테스트에 쓴다): 불길한 서약(`OminousPact`) 한국어 설명은 "잃은 체력에 비례하여 주문력을 75~150, 이동 속도를 50%, 모든 피해 흡혈을 20%을 얻습니다. 스킬 사용 시 현재 체력의 5%를 소모합니다. / 체력이 30%일 때 최대 효과를 얻습니다."가 되어야 하고, 거석상의 용기(`ARAM_CourageoftheColossus`)는 `150~450 (+최대 체력의 4%)`(영어 `150~450 (+4% max Health)`)의 보호막이어야 한다. 집계 줄 "생성한 보호막: @f2@"는 없어야 한다.

### 4.5 동기화 변경

- 지금 흐름(패치가 바뀌었을 때만 전체 재수집)은 그대로다. 증강을 받을 때 언어마다 이름·설명을 만들어 `augment_texts`에 넣거나 갱신한다.
- 지금 "이름 없는 증강은 받지 않음" 규칙은 **한국어 이름 기준** 그대로다. 영어 설명을 못 만든 증강은 그 언어 행만 없고 목록에는 남는다.
- 어떤 언어 문자열 표를 못 받으면 동기화 전체를 실패로 처리한다(지금 실패 처리와 같다: 기존 데이터 유지, 사유 기록, 6시간 뒤 재시도).
- 사라진 증강(비활성)의 설명 행은 지우지 않는다.

```json
  "rarity": "PRISMATIC",
  "iconUrl": "https://raw.communitydragon.org/latest/game/assets/ux/cherry/augments/icons/wisdomofages_large.png",
  "original": { "locale": "en", "name": "Ominous Pact", "description": "Gain <magicDamage>75~150 Ability Power</magicDamage>, …" },
  "translation": { "locale": "ko", "name": "불길한 서약", "description": "…" }
}
```

- `original`은 항상 영어다. `translation`은 `lang`의 것이고, `lang`이 `en`이거나 없거나 지원하지 않는 값이면 `null`이다. 그 언어 행이 아직 없으면도 `null`이다. `original` 행이 없으면 `original`이 `null`이다(화면은 3.7처럼 빈 틀).
- 없는 증강 id는 404 `NOT_FOUND` "없는 증강이에요".
- `description`은 4.3에서 정리한 표식만 들어 있다. 화면은 이 표식을 색으로 바꾼다.
- 기존 `GET /api/augments` 응답은 바꾸지 않는다.

## 6. 권한

모두 공개 읽기다. 쓰기 API는 없다.

## 7. 테스트

**서버**
- 수치 계산기: 부분 종류별 단위 테스트(상수, 범위, 구간, 스탯 계수, 합·곱, 배수, 모르는 종류). `*100` 꼬리. 7칸 값이 다른 `DataValues`.
- 설명 만들기: 문자열 참조 치환, `[스킬]` 치환, 집계 줄 제거, 표식 정리, 못 채운 자리표시자 유지. 4.4의 검증 기준 두 개를 실제 `kiwi.bin.json` 조각으로 확인.
- 동기화: 두 언어 행이 저장되는지, 다시 받으면 갱신되는지, 영어 문자열 표 실패 시 전체 실패인지.
- API: 정상, `lang=en`이면 `translation` null, 없는 id 404, 행 없는 언어 null.

**화면**
- 카드: 표식이 색 `<span>`으로 바뀌고 모르는 표식은 글자만 남는지, `<br>`이 줄바꿈이 되는지, 등급별 테두리 그림과 등급 표가 맞는지.
- 복사: 버튼을 누르면 표식 없는 글이 클립보드에 가고 토스트가 뜨는지, 실패 토스트.
- 언어: 설정이 `localStorage`에 남고 새로고침 뒤 유지되는지, English면 카드가 한 장인지, 한국어면 두 장인지.
- 펼침 영역: 제목 줄·카드·글 목록 순서, 정렬 버튼이 글 목록 쪽에 있는지, 기존 「더 보기」가 그대로인지, 로딩·오류·설명 없음 상태.
- 좁은 화면(`useMediaQuery`)에서 위아래로 쌓이는지.

## 8. 나중에

- 화면 문구 번역(i18n): 3.4의 설정을 읽어 전체 문구를 바꾼다. 그때 로그인 사용자 계정에 언어를 저장할지 정한다.
- 세 번째 언어: 라이엇이 20개 넘는 언어의 문자열 표를 제공하므로 4.2의 행만 늘리면 된다.
- 챔피언 탭 펼침 영역도 같은 한 줄짜리 글 목록으로 맞출지.
- 스킬 증강의 `[스킬]`을 챔피언 글과 묶어 실제 스킬 이름으로 보여줄지.
