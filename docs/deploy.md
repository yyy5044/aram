# 배포 안내

사이트는 AWS Lightsail 서버 한 대(서울)에서 돌아요. 서버 안에서는 Docker Compose로 세 프로그램이 함께 켜져요.

| 이름 | 하는 일 |
|---|---|
| `web` (Caddy) | https 인증서 자동 발급·갱신, 화면 파일 내려주기, API는 백엔드로 넘기기, 업데이트 중 안내 |
| `backend` | Spring Boot 서버 |
| `db` | PostgreSQL |

글·사진·로그인 정보는 모두 서버 디스크에 있고, 서버 전체가 매일 자동 스냅샷으로 백업돼요(7일 보관).

설계: [docs/superpowers/specs/2026-10-25-deploy-design.md](superpowers/specs/2026-10-25-deploy-design.md)

## 1. 처음 한 번 하는 일

Claude가 옆에서 한 단계씩 같이 진행해요. ★는 직접 해야 하는 단계예요.

### 1-1. ★ 도메인 구입

가비아, 호스팅KR, Cloudflare, Porkbun 같은 곳에서 원하는 주소(예: `aram-gg.com`)를 사요. `.com`은 1년에 1.5~2만원 정도예요.

### 1-2. ★ Lightsail 서버 만들기

1. AWS 콘솔에서 **Lightsail**을 열어요.
2. **인스턴스 생성** → 지역 **서울(ap-northeast-2)**, 플랫폼 **Linux/Unix**, 블루프린트 **운영 체제만 → Ubuntu 24.04 LTS**.
3. 요금제는 **월 12달러(메모리 2GB, 2 vCPU, SSD 60GB)**. IPv4가 있는 요금제로 골라요.
4. 이름은 `aram`으로 하고 만들어요.
5. 만든 서버의 **네트워킹** 탭에서
   - **고정 IP 생성**을 눌러 이 서버에 붙여요(무료). 이 IP를 Claude에게 알려주세요.
   - **IPv4 방화벽**에 **HTTPS(443)** 규칙을 추가해요. SSH(22)와 HTTP(80)는 처음부터 열려 있어요.
6. **스냅샷** 탭에서 **자동 스냅샷**을 켜고 시간을 **오전 5시(한국 시간)** 근처로 정해요. 최근 7개가 남아요.

### 1-3. ★ 도메인을 서버에 연결

도메인을 산 곳의 DNS 설정 화면에서 **A 레코드**를 하나 만들어요.

| 호스트 | 종류 | 값 |
|---|---|---|
| `@` (비워 둠) | A | 고정 IP |

반영까지 몇 분~몇 시간 걸려요.

### 1-4. ★ 서버 준비 명령 붙여넣기

1. Claude가 배포 전용 키를 만들고 `server-setup.sh` 실행 명령을 줘요.
2. Lightsail 서버 화면의 **SSH를 사용하여 연결**(브라우저 창)을 열고 그 명령을 붙여넣어요.
3. 마지막에 나오는 **서버 지문**(`SHA256:...`) 줄을 Claude에게 알려주세요.

이 명령이 Docker 설치, 스왑 2GB, `/opt/aram` 폴더, 배포 키 등록을 해요.

### 1-5. ★ 비밀 값 넣기

같은 SSH 창에서 `nano /opt/aram/.env`로 열고 Claude가 알려주는 대로 채워요.

```
DOMAIN=내도메인 (https:// 없이)
POSTGRES_PASSWORD=Claude가 만든 긴 무작위 값
DISCORD_CLIENT_ID=로컬 backend/.env와 같은 값
DISCORD_CLIENT_SECRET=로컬 backend/.env와 같은 값
APP_ADMIN_DISCORD_IDS=관리자 디스코드 ID
```

`Ctrl+O` → `Enter`로 저장, `Ctrl+X`로 나가요. `IMAGE_TAG`는 배포 스크립트가 알아서 넣어요.

### 1-6. ★ 디스코드에 운영 주소 추가

[디스코드 개발자 포털](https://discord.com/developers/applications) → 앱 `aram` → **OAuth2** → **Redirects**에 아래 주소를 추가하고 저장해요. 기존 localhost 주소는 그대로 둬요.

```
https://내도메인/login/oauth2/code/discord
```

### 1-7. ★ 요금 알림 만들기

AWS 콘솔 → **Billing and Cost Management** → **Budgets** → **예산 생성**.

- 비용 예산, 월별, 금액 **15달러**
- 알림 두 개: **실제 금액이 100% 초과**, **예상 금액이 100% 초과** → 내 이메일

예산 2개까지는 무료예요.

### 1-8. GitHub 비밀 값 등록

Claude가 확인을 받은 뒤 `gh secret set`으로 네 가지를 넣어요: `DEPLOY_HOST`(고정 IP), `DEPLOY_USER`(`ubuntu`), `DEPLOY_SSH_KEY`(배포 전용 개인 키), `DEPLOY_KNOWN_HOSTS`(서버 지문). 개인 키 파일은 넣은 뒤 지워요.

### 1-9. 첫 배포

"업데이트해줘"라고 하면 `dev`를 `main`에 합쳐 올리고, GitHub Actions가 테스트 → 이미지 → 서버 반영을 해요. 끝나면 `https://내도메인`에서 확인해요.

## 2. 평소 흐름

```
기능 가지 ──합치기──▶ dev ──(충분히 쌓이면) 합치기──▶ main ──▶ 자동 배포
```

- 기능이 끝나면 `dev`에 합쳐요. "dev에 올려줘" → GitHub에서 테스트만 돌아요.
- "업데이트해줘" → `dev`를 `main`에 합쳐 올려요. 테스트가 모두 통과하면 사이트에 반영돼요(약 10분).
- 진행 상황은 GitHub 저장소의 **Actions** 탭에서 볼 수 있어요.
- 반영되는 30초~1분 동안은 화면에 "잠시 업데이트 중이에요"가 보여요. 로그인은 풀리지 않아요.

## 3. 배포가 실패했을 때

- 테스트가 실패하면 사이트는 그대로고, GitHub이 메일을 보내요.
- 새 버전이 3분 안에 정상으로 뜨지 않으면 **직전 버전으로 자동으로 되돌려요**. 이때도 실패 메일이 와요.
- 원인은 Actions 탭의 실패한 실행 → `deploy` → **서버에 반영** 단계에 백엔드 로그가 찍혀 있어요.
- 서버에서 직접 보려면: `cd /opt/aram && docker compose logs --tail 200 backend`

## 4. 예전 버전으로 돌리고 싶을 때

GitHub **Actions** 탭에서 돌아가고 싶은 커밋의 실행을 열고 **Re-run all jobs**를 눌러요. 그 커밋의 코드로 다시 배포돼요. DB 구조는 되돌리지 않아요.

## 5. 서버를 하루 전으로 복원

서버가 망가졌거나 데이터를 잘못 지웠을 때 써요. **마지막 스냅샷 이후의 글·사진은 사라져요.**

1. Lightsail → 서버 → **스냅샷** 탭에서 원하는 날짜의 자동 스냅샷 → **새 인스턴스 생성**(같은 서울, 같은 요금제).
2. **네트워킹** 탭에서 고정 IP를 옛 서버에서 떼어 새 서버에 붙여요. 새 서버 방화벽에 HTTPS(443)가 있는지 확인해요.
3. `https://내도메인`이 열리고 로그인되는지 확인해요(서버가 켜지면 사이트도 자동으로 켜져요).
4. 서버 지문이 바뀌었으니 Claude에게 GitHub 비밀 값 `DEPLOY_KNOWN_HOSTS` 갱신을 부탁해요.
5. 확인이 끝나면 옛 서버를 지워요(요금이 두 배로 나가지 않게).

## 6. 비용 (한 달, 1달러 ≈ 1,400원)

| 항목 | 금액 |
|---|---|
| Lightsail 2GB (고정 IP 포함) | 12달러 ≈ 16,800원 |
| 자동 스냅샷 | 1달러 미만 |
| 도메인 (.com 연 1.5~2만원) | 약 1,300~1,700원 |
| GitHub Actions, 이미지 저장소 | 공개 저장소라 무료 |
| **합계** | **약 19,000~19,500원** |
